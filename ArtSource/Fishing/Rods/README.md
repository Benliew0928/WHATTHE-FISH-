## Derivation

Run `Tools/Blender/build_fishing_rods.py` with Blender, optionally `-- --render`. Paths resolve from the script's project location; `--root` permits an explicit alternate checkout. The script normalizes each rod to 1.8 m with its butt at the origin, retaining the source's slight shaft curvature. The imported master and both reduced meshes remain editable in each Blender file. Full 2048-pixel source colour, normal and metallic/roughness maps remain in `Textures/`.

Delivery uses new UVs and source-to-delivery colour/normal baking to avoid the triangular paint discontinuities caused by collapsing the original UVs. Each variant shares one material across two LODs. Export PNGs retain 1024-pixel colour and 512-pixel normal data; Unity imports them at 512 and 256 pixels, uses ASTC 6x6 on Android and applies Low mesh packing. The game uses fixed nonmetallic material parameters. The original metallic/roughness map is retained for authoring. These are deliberate mobile derivatives, not lossless copies.

[The model audit](model-audit.json) records source and derived SHA-256 hashes, dimensions, topology, source-vertex surface distances and dependency checks. Both originals have closed edges and finite UVs. The blue rod has one connected component; the teal rod has two closed components. LOD reduction preserves each source's component count and Euler characteristic, retaining its openings. Source-vertex checks are not an all-surface error bound.

Active Blender images are relative or packed. FBX Texture/Video references are verified sibling filenames, with other parsed payloads checked unchanged during the path rewrite. Saved masters and delivery FBXs are reopened. The fixed FBX exporter `Original|FileName` provenance is nonfunctional metadata, not an active dependency; it is the recorded binary-path exception.

## Source quality limits

Meshy softened the grip rings and reel details, made the guide loops uneven and shortened the blue rod's crank arm. The teal rod has a second crank-like shape on the reverse side and irregular colour transitions. These original reconstruction differences remain visible in the review; the integration does not claim to have repaired their shapes. They are static visual candidates, without separate animated reel/rod parts, a line, casting or fishing controls.

See [the game integration and validation report](../../../Docs/FISHING-RODS.md). The game uses independent prefabs on a shared timber rack at `Stand_01`, with grip and tip attachment markers for later work. Do not ship these high-resolution masters or the original GLBs inside Unity Resources/StreamingAssets.
