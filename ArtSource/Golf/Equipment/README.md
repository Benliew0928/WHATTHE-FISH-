# Golf equipment — Meshy sources and delivery

Four independent models were generated and textured on 1 October 2026 from the retained [input references](References/), using the literal **Meshy 6 Lite** option available in the user's Chrome workspace. Meshy did not offer a “6.1 Lite” option. Four geometry and four PBR texture jobs used 80 credits in total. The UI showed public generation and CC BY 4.0; no subscription or top-up was purchased.

## Corrections and remaining flaws

The source ball had 293,996 triangles and an uneven outline. Its actual dimple surface is baked onto a round lightweight sphere. The generated dimples remain larger and less evenly distributed than the reference. Club shafts are continuous and closed, but head proportions are stylized, face grooves are soft and grip accent rings are uneven. These are visible source limitations, not claims of regulation equipment accuracy.

The clubs were aligned from their central shafts, reduced and given fresh UVs with high-to-low texture projection. This avoids the triangular colour discontinuities found in the first reduction. Normals are recalculated after shaft alignment. Unity uses 512-pixel club colour/normal maps, 256-pixel metal/smoothness masks and a 1024×512 ball normal. Android uses ASTC. Ground placement uses the actual terrain beneath the lowest head vertices.

## Reproduce and review

Run Blender 5.1 with `--background --python Tools/Blender/build_golf_equipment.py` from the repository, or give the script's full path from another working directory. The root resolves from the script; optional arguments after `--` are `--root <checkout>` and `--render`. The tool extracts temporary sources under ignored `Builds/GolfEquipment/20261001/`, saves the masters and exports [Unity delivery assets](../../../Game/Assets/_Game/Art/Golf/Equipment/). [Model audit](model-audit.json) records geometry, verified dependencies and integrity hashes with repository-relative paths.

Run Unity's `GolfEquipmentBuilder.Prepare` editor method to configure imports, materials, reusable prefabs and the golf scene. `GolfEquipmentBuilder.BuildWindows` also builds the interactive Windows review. Its launcher is `Builds/WindowsFinal/Review-Golf-Equipment.cmd`; seven buttons show the actual set, ball, faces, reverse driver view and island context, with a walk-around option.

The set stands beside the practice green at island-local (-84, 0, -117). It is part of the golf scene and environment prefab, and is recreated by `RefinedIslandBuilder`. It unloads and returns with that island. This is visual equipment integration; golf-shot controls are outside this change.

See [the delivery and validation report](../../../Docs/GOLF-EQUIPMENT.md) for current player evidence and APK measurements. Physical-phone appearance and frame rate require device testing.
